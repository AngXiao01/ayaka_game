# Harness 设计准则（trace 里每一类“假”，都对应一条准则）

核心原则：**世界的事实归代码，措辞归模型。** 模型只能说“事实表里有的”，事实表里没有的，一律说不知道。

| 症状（来自真实 trace） | 根因 | 准则 | 落点 |
|---|---|---|---|
| 大白天说“天快亮了，带上照明” | 钟点没给模型，它凭语感编 | 时间与天色由代码算出，写进每个提示；说到时间只许照抄 | `GodEnv.daylight()`、NPC 情境、选项提示、核对员 |
| 窗台灰尘少、门窗加固、窗高两丈 | 现场的物理格局没写在任何地方 | 每个地点有 `layout` 事实表；数字只以它为准 | `world.json` 的 `layout`，NPC 提示，核对员 |
| 玩家走了，绫华“往花见坂去了” | 模型从“你去花见坂吧”里抽出了她自己的去向，代码照做 | 会改变世界状态的动作（移动、传话）由代码按身份和场合校验：玩家离开时、委托人，一律不执行 | `DialogueSession._world_moves` |
| 托马明明请我帮忙，却答非所问地岔开 | 自己人也套了“拿凭据来换”的卡点；卡住时模型只会岔话题 | 卡点必须有故事里的理由，并且要被说出来；盟友不设无理由的卡点；锁着的事被问到要直接回应，不许岔开 | 任务文件里盟友信号不设条件；`locked_info` 的措辞 |
| 把“失窃的委托”递给托马，他像第一次看见 | 不知道谁本来就知道什么 | 每个角色有 `knows_clues`：一开始就知道的事，不进出示菜单，被出示也不意外 | 角色卡、`GameEngine`、NPC 情境 |
| 叫绫华“绫华姐”；问句被当成“我做过” | 称呼没规定；抽取没要求原文依据 | 称呼是角色卡的数据；声明必须是原话的片段并带“已做过”的口气 | `addressed_as`、`validate_claims` |

## 每一轮 NPC 回复的流水线

1. **评估**（只判断，不说话）：接不接得上、情绪、好感信任、打算怎么回。
2. **说话**（只写台词）：读情境（时间天色、格局、立场、本来就知道的事、刚给他看的东西）。
3. **核对**：台词对照事实表和常识，矛盾 / 编造 / 说不通就带着意见重说一次。
4. **记录**：哪些待说的事说出口了、有没有新设定、谎话、带话、去向。
5. 代码执行：信号结算、传话、移动、时间。**任何改变世界的动作都由代码按规则校验后执行**。

## 加新内容时的自查清单

- 这个 NPC 在这个时间、这个地点，**能不能**知道 / 做这件事？（作息、`knows_clues`、`layout`）
- 如果他不肯说，**理由**是什么？写进 `lock_hint`，并且是他会当面说出口的理由。
- 例句里有没有案情词？（测试会拦）
- 称呼写了吗？（`addressed_as`）
