# 参考的开源项目：读了什么、学到什么、没学什么

标注：【读了源码】= 我取回并读了对应源文件；【只读了 README】= 只看到自述，细节没核实。

## 1. Generative Agents（Stanford / `joonspk-research/generative_agents`）【读了源码】

读的文件：`reverie/backend_server/persona/cognitive_modules/{perceive,retrieve,reflect}.py`。

| 机制 | 代码里的做法 | 我们的对应 |
|---|---|---|
| 感知过滤 | 视野半径 → **注意力带宽**（只留离自己最近的前 N 条事件）→ **留存去重**（和最近 N 条事件重复的跳过）| 复读检测 `_echoes`、重复提问 `_repeated_question` |
| 记忆打分 | 近因、相关、重要三项各自 min-max 归一到 [0,1]，权重 0.5 / 3 / 2，取前 30；被取出的记忆刷新 `last_accessed` | `MemoryStore.retrieve`（BM25 + 重要度 + 近因，权重不同；没做访问刷新） |
| **反思触发** | 每条新记忆把 `importance_trigger_curr` 减去它的重要度，减到 ≤ 0 才反思，反思完重置 | **本轮已采用**：新记忆重要度累计到 `REFLECT_AT` 才反思 |
| **反思内容** | 先从最近记忆里挑出 3 个“焦点问题”，各自检索相关记忆，再生成最多 5 条洞见，**每条洞见带它依据的记忆编号**；洞见作为带三元组、重要度和 30 天过期的“想法”写回记忆流 | **本轮已采用其中的“带证据”**：反思必须写出依据的记忆编号并存进 `extra.evidence`；焦点问题与过期没做 |
| 对话后反思 | 谈话结束写两条想法：“为我的计划”和“备忘”，证据是那段聊天 | 反思里的 `next`（下次打算）对应 |

局限：它的“想法”没有校验，洞见失败时会回落成 `{"this is blank": "node_1"}`；我们的反思要求证据编号合法，不合法就让模型重写。

## 2. Concordia（Google DeepMind / `google-deepmind/concordia`）【读了源码：`event_resolution.py`、`make_observation.py`；其余只读了 README 和文件清单】

- 实体 = 容器，行为来自挂在它身上的**组件**（记忆、目标、感官）；玩家和 Game Master 都是实体。我们的“角色卡 + 流水线各步”是同一思路的简化版。
- **GM 的事件裁决**是一条思维链：“这个行动属于哪一类、玩家有没有能力” → “别人有没有自愿行动（问那个人的 agent：这是你会做的事吗？）” → “成功与否（简单的事倾向成功，除非有具体理由失败）” → “后果” → 把原话保留进事件 → “故事是否重复？重复就注入一个小波折” → “是否该切到下一场景”。
  我们用 `ActionResolver`（动词 + 概率）和 `Director` 覆盖了其中一部分；“故事重复就注入波折”对应我们的 beat 选择里的耐心项。
- **观察队列**：每个实体一条队列，事件**只送达一次**，已经见过的文字会被剔除。**谁知道这件事**由上游决定（LLM 问“哪些实体知情？”），这个组件本身不做知识过滤。
  这也提醒我们：知识边界必须在“送进谁的队列”这一步由代码管，我们的 `secrets` 注册表就在做这件事。
- 没采用：多 GM 切换、问卷、收益矩阵。

## 3. AI Town（a16z / `a16z-infra/ai-town`）【读了 `ARCHITECTURE.md`；`convex/agent` 的源码没读】

- **所有对世界的改动都走 `inputs` 表**（带递增编号和时间戳），游戏状态不直接写；人和 agent 提交同样的输入。
- 引擎确定性、单线程；agent 的 LLM 调用是异步“操作”，**一次只跑一个，结果只能通过提交输入来改变状态**。
- 对话后 GPT 做摘要 → 向量化 → 下次对话前取最相似的 3 条；向量按文本哈希缓存。
- 我们的对应：世界状态都由 `GodEnv` 的方法改、模型只提议——精神一致，但我们没有做成“事件溯源”（trace 是日志，不是状态来源）。

## 4. PLAYER*（`alickzhu/PLAYER`，谋杀之谜）【读了论文网页版，没读仓库代码】

- 每个 agent 只有自己的剧本和亲历的信息，别人的事只能通过互动知道。
- **悬疑矩阵 + 三个传感器**（情绪、动机、机会）；**提问有预算，同一个人重复问收益递减**；筛选是“软”的，新证据可以让嫌疑人复活。
- 本轮采用：**重复提问递减**（同一问题再问，NPC 会说“我刚说过了”而不是原样复读）。
- 没采用：悬疑矩阵（对玩家建模不是我们的瓶颈）。

## 5. 其余看过但没深入

- **Mantella / SkyrimNet**【只读了 README 摘要】：给 NPC 加记忆和对游戏内事件的感知，后台线程异步处理 LLM。我们的 trace 与异步无关，没有借鉴。
- **MIRAGE / WhodunitBench / Holmes**【只看到简介】：谋杀之谜评测与小型侦探游戏；Holmes 用 LangChain + ChromaDB 做 RAG。体量和成熟度不足以作为架构参照。
- **SillyTavern World Info**：关键词触发 + 字数预算，已用于 `fit_state`。

## 总结：本轮从真实代码里采用了什么

1. 累计重要度触发反思（GA）。
2. 反思必须带证据（GA 的洞见带记忆编号）。
3. 重复提问递减（PLAYER*，也呼应 GA 的“留存去重”）。

没做、且值得做的：反思的**焦点问题**步骤、记忆的**访问刷新**、把世界改动做成**事件溯源**（AI Town 的 inputs 表）。
